What the simulation is demonstrating

  • Stage gating. Each record carries a status, and every screen checks it before accepting input. That single rule is what makes the data trustworthy — steps cannot be skipped, repeated or completed out of order, no matter how busy the line is.
  • One record, not four slips. The defect report, the repair, the verification and the final judgement all attach to one tracking ID, so a question about a part has exactly one answer.
  • Master-data-driven input. Every field is a selection from a governed list, never free text — which is what keeps the captured data clean enough to analyse later.
  • Role accountability. Reporter, repairer and inspector are captured separately at each stage, because a shared shop-floor tablet still has to answer “who did this”.
  • The rework path. When verification fails, the record routes to a second repair pass rather than closing — the failure is part of the designed flow, not an exception someone handles off-system.
