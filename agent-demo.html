What this is actually doing

Every production agent I have deployed follows the same four-step decision flow, and this prototype exposes each step rather than hiding it behind a chat bubble:

  • Intent classification — scores the request against known categories and shows its confidence, because a triage agent that cannot say how sure it is cannot be trusted to act.
  • Entity extraction — pulls out the system, the target and the urgency, which is what turns a sentence into an actionable ticket.
  • Policy check — decides whether this category is genuinely safe to automate. This is the step that matters most: the value is not automating everything, it is knowing what not to automate.
  • Action or escalation — resolves it, or hands to a human with the triage work already done, so the person starts from a classified request rather than a blank one.

In production the classifier is model-backed and the actions call real systems; the confidence thresholds, the policy gate and the escalation path are the parts I actually design — and they are reproduced faithfully here.
